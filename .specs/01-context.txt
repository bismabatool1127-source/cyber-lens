3. Our Project

The name of our project is:

CYBER-LENS

Tagline

Your Digital Security Guard

Cyber-Lens is a web-based AI-assisted cybersecurity application designed to help ordinary users identify
potentially dangerous digital communication and suspicious online information.

The core idea is:

          Before trusting a suspicious digital item, let Cyber-Lens examine it.

The application will initially focus on three types of inputs:

      1. Suspicious URLs
      2. Emails
      3. Phone numbers

4. The Problem We Are Solving

Ordinary internet users frequently encounter:

        · phishing links
        · fake login pages
        · suspicious emails
        · impersonation attempts
        · fraudulent messages
        · suspicious phone numbers
        · misleading requests for personal or financial information

                                                                         2
Many users cannot easily determine whether something is legitimate.
Cyber-Lens should provide a simple interface where a user can submit suspicious information and
receive an understandable security assessment.
The application should therefore prioritize simplicity and explainability.
A non-technical person should be able to use it.

5. Core User Experience

The intended workflow is:
User opens Cyber-Lens

Chooses what they want to check:
URL / EMAIL / PHONE

Provides the information

Cyber-Lens analyzes it

The system produces:

        · risk level
        · risk score
        · detected indicators
        · explanation
        · recommended action
The user should not need cybersecurity knowledge to understand the result.

6. Cyber-Lens Is NOT Simply a Database Lookup

This is extremely important.
Do NOT design the application around the logic:
"If it exists in the database  malicious. If it doesn't exist  safe."

                                                                         3
That would create false confidence.

A previously unknown phishing URL may not exist in a database.

Instead, Cyber-Lens should combine multiple forms of analysis where technically practical within the 4-
day timeframe:

        · format validation
        · structural/rule-based indicators
        · threat-intelligence/database matching
        · suspicious characteristics
        · email-content analysis
        · URL analysis inside emails
        · other appropriate indicators
The final result should represent an overall risk assessment.

7. Risk Classification

Cyber-Lens should preferably use three broad classifications:

LOW RISK

No significant suspicious indicators were detected.

This should NOT mean that the item is guaranteed to be safe.

SUSPICIOUS

One or more concerning indicators were detected, but there is insufficient evidence to classify the item
as definitively malicious.

HIGH RISK / MALICIOUS

Strong evidence indicates that the item is potentially dangerous, including known malicious records or
multiple strong indicators.

Never claim:

"100% safe."

Prefer language such as:

"No known threat detected."

8. URL Analysis

A user should be able to enter a URL.

Cyber-Lens should check, where practical:

        · URL syntax
        · URL structure
        · suspicious characteristics
        · domain characteristics
        · known threat records
        · other relevant indicators
The system should return an explainable result.

Example concept:

        · Known malicious indicator
        · Suspicious URL structure
Recommendation: "Do not open this link or provide sensitive information."

9. Email Analysis

Users should be able to provide:

        · sender email address
        · subject
        · email body
Cyber-Lens should analyze, where practical:

        · sender format
        · sender/domain characteristics
        · suspicious language
        · urgency
        · requests for sensitive information
        · phishing/social-engineering indicators
        · URLs contained inside the email
If an email contains URLs, those URLs should ideally be passed through the same URL-analysis engine
rather than creating an entirely separate URL detection system.

The email scanner should produce an overall risk assessment.

10. Phone Number Analysis

We also want to include a simple phone-number security check.

                                                                         5
Because the project has only four days, this feature should remain intentionally lightweight.

The system can check:

        · basic phone-number format
        · country-code structure where appropriate
        · obvious formatting problems
        · known suspicious/malicious records if available
        · other simple indicators
Do not allow the phone-number feature to consume development time needed for the core URL and
email scanners.

11. Cloud-Based Concept

Cyber-Lens is intended to be an online application.

When users submit information for analysis, the backend/server can perform the required analysis and
query the relevant threat-intelligence/data sources.

The system should be designed so that threat information can be updated centrally rather than
requiring users to download a new version of the application.

However, do not create unnecessary cloud infrastructure.

Use the simplest reliable architecture that can support the hackathon demonstration.

12. AI's Role

AI should be used where it genuinely provides value.

Potential AI-assisted functionality includes:

        · analyzing email language
        · identifying phishing/social-engineering characteristics
        · helping interpret suspicious content
        · producing understandable explanations
Deterministic logic should be preferred for things such as:

        · format validation
        · structured checks
        · known database matching
        · straightforward rule-based indicators
The system should ideally be a hybrid AI + rule-based security analysis system, rather than blindly
asking an AI model:

"Is this safe?"

          Detect  Explain  Recommend

          Detect  Label
